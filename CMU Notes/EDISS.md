- What is Distributed system
	- Its a solution where you have multiple components of a software solution, running on different machines.
	- These components doesn't use low-level communication methods (Network level), but instead uses the Application layer communication methods
	- Distributed systems require "Location Transparency", where each components are named (Very important)
- Service Oriented Architecture (SOA)
	- Service
	- Microservices vs SOA
		- A microservices design pattern is a SOA pattern, but not all SOA patterns are microservices
	- Monolithic style
		- When all the services are packaged into one deployment artifact, its a monolith
		- Any change in the services, requires rebuilding and redeploying the entire deployment artifact (i.e. Monolith)
		- Monolithic style also falls under the SOA, as we have different components such as DB, frontend, etc. which are deployed on different machines, which makes it distributed, but in most of the cases the backend services are clubbed together which is the monolith
	- Microservices
		- Its a SOA style, where you have multiple small services, where each of them are running in its own process, where they communicate using lightweight protocols such as HTTP
		- The services in this single deployment unit must be cohesive in nature
		- Benefits
			- Easier Deploybility 
			- Better Availability and Reliability
			- Modifiability and Reusability, having more independence on the service
			- Scalability and Management 
		- Challenges
			- Performance, due to communication over network
			- Deployability in terms of Devops POV
			- Higher Memory footprint at runtime, due to re-usage of libraries
			- Testability, especially for E2E tests
			- Security
				- Services in individual microservices generally communicate using HTTPS, or may Message brokers, which is synchronous and asynchronous
				- Generally, we perform IP Allowlisting, where we allow certain IP address in different environments
		- Types of Connectors
			- Synchronous
				- REST
				- RPC based (such as gRPC and Graphql)
				- Component Based (such as EJB)
			- Asynchronous

	- Microservices vs Monolith
		- The major difference is in the fact that these individual services are independently deployable. This deployment constraint is the major distinguishing factor
		- Sometimes you can have more than one service in a single deployment unit as well
		- There is a subtle difference in Monolith having 2 services vs Microservices having 2 services
			- In this case, even though the deployment unit is a single unit, but in case of monolith it is expected that the 2 services have less cohesion with other services
