- Challenges of Internet
	- Internet operates at an enormous scale
	- Internet must handle diverse uses of applications
	- Internet is Asynchronous, making us to deal with Stale data
	- Internet must Handle failures at scale
- Internet is all about designing the protocols
- Need of Headers
	- Packet Header
		- Contains the metadata, which contains the Source and the destination address
		- The data is stored in the payload
	- Headers are standardized in terms of the format
	- Headers are wrapped on top of the existing payload as we move down the levels and in the reverse fashion
	- Different layers use different layering schemes
	- When a packet passes through multiple hops, the packet headers at the Layer 2 are changed accordingly based on the forwarding tables it has.
- End hosts must implement all the layers on OSI model, where as the routers/ switches will not implement all the layers
	- So, the routers and switches unwraps only until layer 3 or 2, and wraps again with new data for the layers.
- Layer 4-7 are built for reliability for the data transfer implemented using the Layer 1-3, because Layer 3 only offers "Best Effort Delivery"
- Internet Design Principles
	- Decentralized Protocol
		- Each device operating on its own, where we dont have central mastermind
	- Best-Effort Service Model
		- Since Layer 3 doesn't guarantee that the packets are delivered
	- Route around trouble
		- Making sure that network is resilient to failures
	- Dumb infrastructure
		- Routers simply route the packets, where they are dumb enough to not check the insides of the packet
	- End-to-end principle
		- Layer 4 to 7 are only implemented in the end hosts, not the routers or switches
		- We cant simply rely on the routers to provide the correctness of the data transmission as they can be faulty at any point of time. Instead it is the job of the end host to make sure that it receives all the required packets
			- We can break this rule for performance that is if we have enable routers to check the packets dropped, and it automatically send duplicate packets, then it can improve the performance, but the end host shouldnt depend on the router for data correctness
	- Layering
		- Layering in OSI stack provides us with abstraction, which makes development easier
	- Federation via Narrow-waist interface
		- This says that Layer 3 only acknowledges the IP protocol
		- Other layers such as Layer 4 and 7 are decided between the hosts, and layers 1 and 2 are decided between routers
			- We can establish communication with SMTP (7), TCP (4), Ethernet (2) and Copper wires (1), but Layer 3 stays same
		- If layer 3 uses some other protocol than IP, such as bluetooth, then it is not a part of the Internet
		- Demultiplexing
			- De-multiplexing helps layer 3 to understand to which protocol it needs to send on Layer 4, and similarly for Layer 4, this helps in sending the data at the right ports i.e., individual applications
		- Implementation of Layers on Host
			- Layer 1 and 2 are in the hardware, such as on NIC
			- Layer 3 and 4 exist on the OS, implemented within the software
			- Layer 7 exist on the application
- Statistical multiplexing
	- Before understanding the multiplexing, we should how do we share resources between different data transfers i.e., you cant have single router for each of the data flows, instead you are supposed to share them
		- There are 2 ways to do that 
			- Static Allocation: Each flow has a static resource allocation
			- Statistical multiplexing: Dynamically allocates to users based on the demand
	- Statistical multiplexing can be simply defined Peak of Aggregate demand < Aggregate of peak demands
	- Types of implementations for statistical multiplexing
		- Circuit Switching
			- End hosts reserve the resources used for data transfer before beginning, and release them after the transfer is completed
			- Initially, the sender sends a reservation request to the receiver, and all the routers along the way basically accept the request and set aside the requested bandwidth for this
			- After completion, the sender again sends the tear request to release the resources across the circuit formed
			- The difference between static allocation and circuit switching is circuit allocation is similar to reservation of resources for some time.
		- Packet Switching
			- In this approach, each of the packets flow independently depending the current usage of the routers
			- Tries to reach Best effort delivery using this approach
	- Which of them is better
		- Abstraction
			- Circuit switching is more convenient as you get a guarantee of the resources
		- Efficiency
			- Packet Switching is more efficient than Circuit Switching
				- Requires a lot of time for sending the reservation and teardown requests
				- **Bursty traffic** can lead to wasted resources
				- **Consistent traffic**, perform with equal efficiency for both methods
		- Fault tolerance
			- Packet Switching handles failures than Circuit switching, as any fault in middle nodes requires the end hosts have to re-establish the circuit
		- Complexity
			- Packet switching is easier to implement, as they don't require to keep track of the reservations
		- In summary, Circuit switching provides better performance on the required bandwidth and becomes much more predictable for the developers, where as the Packet switching ism more efficient, reliable and fault tolerant
- Links
	- Properties of Links
		- There are 3 main properties of Links to capture the performance
			- Bandwidth
				- Number of bits we can send through the link in 1 sec
			- Propagation Delay 
				- Amount of time taken for an individual bit to travel from the sender to the receiver
				- Sometimes, latency is also referred as the propagation delay
			- BDP - Bandwidth propagation delay
				- It is the cross product of the bandwidth and the propagation delay
	- Time Delay
		- Calculate total time to transfer 800 bit packet through a link which can support 1Mbps == 1 million bits per second bandwidth and and propagation delay of 1ms
			- For the first bit to be transferred, it takes (1/1 million)` i.e., bandwidth` + (1ms), so totaling 0.001001 seconds
			- Similarly for the second bit to transfer it takes 0.001002 seconds in total, assuming that it gets sent after the first bit
			- Hence for all the 800 bits to be sent, it takes 0.0018 seconds i.e., 1.8ms
		- The time taken for a packet to be transferred known as **Packet Delay** can be said as `Time Delay = Transmission Delay + Propagation Delay`
		- Transmission delay is calculated as `Packet size/ Bandwidth`
		- So, **Time Delay** is a function which depends two properties i.e., bandwidth and propagation delay
		- If the packet size is big, bandwidth plays a big role, else propagation delay
	- Overloaded links
		- Sometimes, the router gets a huge influx of incoming packets, where the router tries to maintain a queue order for the packets that are sent, but if the queue overflows, it leads to dropping of the packets.
		- Hence, the new `Time Delay = Transmission Delay + Propagation Delay + Router Queuing Delay`
